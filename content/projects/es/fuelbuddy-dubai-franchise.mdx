La expansión de FuelBuddy en los Emiratos Árabes Unidos necesitaba su propia app de franquicias: el mercado de Dubái tenía requisitos regulatorios, de seguridad y de flujo de trabajo distintos a los de las plataformas existentes, lo suficiente como para que reutilizar la antigua no encajara bien. Construí la Aplicación de Franquicias de Dubái desde cero, tanto en el frontend como en las APIs CRUD que hay detrás.

## Lo que construí

- **Nuevo frontend desde cero:** Construí el sistema de componentes desde el principio, lo que permitió que la app fuera más responsive y estuviera mejor armada que las versiones anteriores a las que reemplazaba.
- **Mis propias APIs CRUD sobre Hasura:** Construí las APIs de datos del backend sobre las que funciona la app, usando el motor GraphQL de Hasura sobre la base de datos para exponer las operaciones CRUD que necesitaba, de modo que pude diseñar la capa de datos de principio a fin en lugar de esperar a endpoints de backend separados.
- **Capa de datos con TanStack Query:** Usé TanStack React Query en el frontend para consumir esas APIs  - caché, refetch en segundo plano y actualizaciones optimistas -  para que la interfaz se mantuviera rápida y consistente sin mucho cableado manual de estado.
- **Autenticación y seguridad:** Rehíce la autenticación, el manejo de tokens y la validación de los payloads de la API para cumplir los requisitos de conformidad de la región.

## Por qué importó

El resultado cumplió los requisitos más estrictos del mercado de Dubái y estableció un estándar interno más limpio sobre cómo se construyen estas apps. La capa de datos revisada también redujo las llamadas de red redundantes, lo que mantuvo la experiencia ágil para los socios de franquicia.
