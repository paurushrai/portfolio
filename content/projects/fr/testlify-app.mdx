[Testlify](https://testlify.com/) est une plateforme d'évaluation de compétences et d'entretiens. Dans son générateur de tests destiné aux recruteurs, j'ai construit l'interface de rédaction de trois types de questions pilotées par IA, voix, vidéo, et simulation de chat, que les recruteurs utilisent pour configurer des évaluations automatisées de candidats : limites de durée d'enregistrement, configuration des prompts IA, notation par compétences, et choix de voix de synthèse vocale.

## Ce que j'ai construit

- **Rédaction de questions IA vocales :** Construction de l'interface de configuration des questions d'entretien IA basées sur la voix dans le générateur de tests, limites d'enregistrement, configuration des prompts IA, et notation par compétences.
- **Intégration au générateur de questions :** Intégration des types de questions voix, vidéo, et simulation de chat dans le flux du générateur d'évaluations du recruteur.
- **Style et outillage :** Contribution au style des composants pour l'interface des questions voix/chat, ainsi qu'à la configuration de l'outillage du dépôt (ESLint, Husky, Renovate, configuration Tailwind).

## Pourquoi c'était important

Les questions IA voix, vidéo, et chat sont le moyen par lequel les recruteurs configurent les évaluations d'entretien automatisées de Testlify. Ce travail a rendu ces types de questions configurables et cohérents au sein du même design system partagé utilisé sur l'ensemble de la suite produit de Testlify.

## Une petite contribution, dans une base de code massive

Ce dépôt est le tableau de bord recruteur/admin de Testlify : 16 216 commits, des dizaines de contributeurs, actif depuis septembre 2021. Mes propres commits en représentent 86, environ un demi pour cent, sur environ un an et demi. La majeure partie de ce compte se trouve dans un sous-module git `component-library`, le même design system Vue partagé déjà couvert comme [étude de cas à part entière](/projects/testlify-component-library) ; en dehors de ce sous-module, le vrai travail porte sur un ensemble ciblé de fichiers : la modale de question vocale, la vue des questions d'entretien qui relie les types de questions au générateur, et le style et l'outillage qui les entourent.

## Ce que « entretien IA multimodal » signifie réellement ici

Cette application est le côté recruteur du produit : là où un recruteur configure ce qu'une question pilotée par IA demande réellement, pas là où un candidat y répond en direct. Voix, vidéo, et simulation de chat sont des *types* de questions qu'un recruteur configure dans le générateur de tests, chacun avec sa propre limite de durée d'enregistrement, son propre prompt IA, sa propre grille de notation par compétences, et (pour la voix) un choix de voix de synthèse vocale. L'expérience d'entretien côté candidat, qui fait vivre ces questions configurées, tourne dans une application séparée, ailleurs dans la stack de Testlify.

## Modèle de données et échelle

- 16 216 commits sur plus de 4 ans, avec un contributeur principal responsable à lui seul de plus de 1 800 d'entre eux, une base de code d'équipe véritablement vaste et de longue durée, pas un petit projet.
- Le design system partagé est consommé comme un sous-module git plutôt que copié-collé ou forké, gardant cette application sur le même design system versionné que les trois autres produits de Testlify.

## Stack

[Vue](https://vuejs.org/) 3, [TypeScript](https://www.typescriptlang.org/), [Vuex](https://vuex.vuejs.org/) pour l'état, [Vite](https://vite.dev/), le [design system Testlify](/projects/testlify-component-library) partagé comme sous-module git, [ESLint](https://eslint.org/), [Husky](https://typicode.github.io/husky/), [Renovate](https://docs.renovatebot.com/) pour les mises à jour de dépendances, [Tailwind CSS](https://tailwindcss.com/).
