Это портфолио — приложение на **Next.js 14 App Router**, созданное как живой инженерный артефакт, а не шаблон. Каждое архитектурное решение отражает тот же производственный подход, что применяется в корпоративных системах: корректность, наблюдаемость и измеримая производительность. Сайт достигает **99/100 на десктопе и 97/100 на мобильных устройствах по Lighthouse**, а также идеальных 100 баллов по Доступности и SEO.

## Технический охват и вклад

- **Архитектура i18n на 12 языков:** Разработал и реализовал полностью кастомную систему интернационализации с нуля — без сторонних библиотек. Создал типобезопасный `LanguageContext` со строго типизированной картой переводов для английского, немецкого, испанского, французского, хинди, итальянского, японского, корейского, португальского, русского, турецкого и китайского языков. Переключатель языков сохраняет выбор пользователя через `localStorage` и динамически обновляет атрибут `<html lang>`, гарантируя корректную локаль для экранных читалок и поисковых роботов в любой момент. Каждая строка интерфейса — включая подписи к полям формы обратной связи, состояния ошибок и тексты CTA — полностью локализована для всех 12 локалей.

- **Canvas-анимация и оптимизация производительности:** Написал систему частиц уровня WebGL, используя нативный Canvas 2D API с магнетизмом от мыши, физикой затухания альфа-канала и плавным переносом через границы. Выявил и устранил критическое узкое место принудительного reflow — вынес вызовы `getBoundingClientRect()` из горячего пути `mousemove` в кешированный `ref`, обновляемый только при изменении размеров, что сократило DOM-нагрузку на кадр с O(n) до O(1). В сочетании с RAF-троттлингом обновлений состояния мыши и ленивой загрузкой через `next/dynamic` это позволило полностью убрать частицы с критического пути рендеринга и поднять показатель Lighthouse на десктопе до **99/100**.

- **Стек аналитики без слепых зон от блокировщиков:** Создал двойную аналитическую установку (Umami + Google Tag Manager) и построил прокси-перезапись Next.js, маршрутизирующий всю телеметрию через домен первой стороны (`/um/script.js` → `cloud.umami.is`, `/um/api/send` → `api-gateway.umami.dev`). Это устраняет 20–40% тихих потерь событий, характерных при загрузке аналитических скриптов со сторонних доменов, блокируемых uBlock Origin и Brave. GTM управляет тегом GA4 на стороне сервера, консолидируя всё управление тегами в одном месте.

- **SEO и набор структурированных данных:** Реализовал JSON-LD схему `Person`, hreflang-ссылки для всех 12 локалей, канонические URL для каждого маршрута и динамический `generateMetadata` на каждом slug проекта. Настроил `generateMetadata` для генерации Open Graph и JSON-LD `SoftwareApplication` для каждого проекта — это удовлетворяет валидатор структурированных данных Google и устраняет сигналы дублированного контента между локализованными маршрутами.

- **Доступность по WCAG 2.1 AA:** Провёл полный аудит доступности и устранил все выявленные нарушения — добавил визуально скрытую ссылку «перейти к содержимому», ввёл глобальные кольца `:focus-visible` для клавиатурной навигации через единое CSS-правило, исправил соотношение контраста текста и фона по всему основному тексту (zinc-500 → zinc-400 на тёмных поверхностях удовлетворяет AA-контрасту 4.5:1+) и применил `aria-hidden` к декоративным canvas-элементам. Рефакторировал переключатель языков из несемантического `listbox` в корректную ARIA-структуру `menu`.

- **Типобезопасный контент-пайплайн:** Настроил Contentlayer для обработки MDX-файлов проектов в полностью типизированный статический JSON во время сборки с вычисляемыми полями `slug` и `locale`, получаемыми из структуры пути файла. Добавление новых проектов не требует изменений кода — достаточно поместить MDX-файл в правильную папку локали, и он появится на сайте при следующем деплое. Накладные расходы на парсинг во время выполнения устранены полностью.

- **Serverless-подсчёт просмотров страниц:** Реализовал serverless Edge Function для анонимного подсчёта просмотров с использованием SHA-256-хешированных IP-адресов для дедупликации — без cookies, без хранения персональных данных. Счётчики ревалидируются в 60-секундном ISR-окне, что делает статистику просмотров проектов практически живой без ущерба для статической модели доставки.
