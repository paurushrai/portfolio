FuelBuddy の UAE 展開には、独自のフランチャイズアプリが必要でした。ドバイ市場は規制、セキュリティ、ワークフローの要件が既存のプラットフォームと異なり、古いものを流用するのは適切ではありませんでした。私はドバイのフランチャイズアプリケーションをゼロから、フロントエンドと背後の CRUD API の両面にわたって構築しました。

## 作ったもの

- **フロントエンドをゼロから新規に:** コンポーネントシステムを一から新しく構築しました。これにより、置き換え対象の旧バージョンよりも応答性が高く、まとまりのよいアプリになりました。
- **Hasura 上の自作 CRUD API:** アプリが動く土台となるバックエンドのデータ API を構築しました。データベースの上に Hasura の GraphQL エンジンを使い、必要な CRUD 操作を公開したので、別のバックエンドエンドポイントを待つのではなく、データ層をエンドツーエンドで設計できました。
- **TanStack Query 上のデータ層:** フロントエンドではそれらの API を消費するために TanStack React Query を使いました。キャッシュ、バックグラウンドでの再取得、楽観的更新により、手作業の状態管理を大量に書かずとも UI を高速かつ一貫した状態に保てました。
- **認証とセキュリティ:** 地域のコンプライアンス要件を満たすため、認証、トークンの取り扱い、API ペイロードの検証を作り直しました。

## なぜ意味があったか

その結果、ドバイ市場のより厳しい要件を満たすとともに、これらのアプリの作り方について、社内のよりきれいな標準を打ち立てました。見直したデータ層は冗長なネットワーク呼び出しも減らし、フランチャイズパートナーにとって快適な速さを保ちました。
