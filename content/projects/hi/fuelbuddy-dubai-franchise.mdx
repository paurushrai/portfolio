FuelBuddy के UAE विस्तार को अपने खुद के फ्रैंचाइज़ ऐप की ज़रूरत थी — दुबई बाज़ार की नियामक, सुरक्षा और वर्कफ्लो ज़रूरतें मौजूदा प्लेटफॉर्म से अलग थीं, इतनी कि पुराने को दोबारा इस्तेमाल करना ठीक नहीं बैठता था। मैंने Dubai Franchise Application को शून्य से बनाया, फ्रंटएंड और उसके पीछे के CRUD API दोनों में।

## मैंने क्या बनाया

- **शून्य से नया फ्रंटएंड:** कंपोनेंट सिस्टम को नए सिरे से बनाया, जिससे ऐप उन पुराने वर्ज़नों की तुलना में ज़्यादा रेस्पॉन्सिव और बेहतर ढंग से जुड़ा हुआ बना जिनकी जगह उसने ली।
- **Hasura पर मेरे अपने CRUD API:** ऐप जिन बैकएंड डेटा API पर चलता है, उन्हें बनाया, डेटाबेस के ऊपर Hasura के GraphQL इंजन का इस्तेमाल करते हुए ताकि मुझे ज़रूरी CRUD ऑपरेशन एक्सपोज़ हों — इस तरह मैं अलग बैकएंड एंडपॉइंट का इंतज़ार करने के बजाय डेटा लेयर को शुरू से आखिर तक खुद डिज़ाइन कर सका।
- **TanStack Query पर डेटा लेयर:** उन API को इस्तेमाल करने के लिए फ्रंटएंड पर TanStack React Query का उपयोग किया — कैशिंग, बैकग्राउंड रीफेचिंग, और ऑप्टिमिस्टिक अपडेट — ताकि UI बिना ज़्यादा मैनुअल स्टेट जोड़-तोड़ के तेज़ और एकसमान बना रहे।
- **Auth और security:** क्षेत्र की अनुपालन ज़रूरतों को पूरा करने के लिए ऑथेंटिकेशन, टोकन हैंडलिंग, और API पेलोड वैलिडेशन को दोबारा तैयार किया।

## यह क्यों मायने रखता था

नतीजा दुबई बाज़ार की सख्त ज़रूरतों पर खरा उतरा और यह भी तय किया कि ये ऐप्स अंदरूनी तौर पर कैसे बनें, इसका एक ज़्यादा साफ स्तर। संशोधित डेटा लेयर ने फालतू नेटवर्क कॉल भी कम किए, जिससे फ्रैंचाइज़ पार्टनर्स के लिए अनुभव तेज़ बना रहा।
