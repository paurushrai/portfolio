A expansão da FuelBuddy nos Emirados Árabes Unidos precisava de seu próprio app de franquia, o mercado de Dubai tinha requisitos regulatórios, de segurança e de fluxo de trabalho diferentes das plataformas existentes, o suficiente para que reaproveitar o app antigo não fosse uma boa opção. Construí o Aplicativo de Franquia de Dubai do zero, tanto no frontend quanto nas APIs CRUD por trás dele.

## O que construí

- **Novo frontend do zero:** Construí o sistema de componentes do zero, o que permitiu que o app fosse mais responsivo e melhor estruturado do que as versões mais antigas que ele substituiu.
- **Minhas próprias APIs CRUD na Hasura:** Construí as APIs de dados de backend sobre as quais o app roda, usando o motor GraphQL da Hasura sobre o banco de dados para expor as operações CRUD de que eu precisava, assim pude desenhar a camada de dados de ponta a ponta em vez de esperar por endpoints de backend separados.
- **Camada de dados com TanStack Query:** Usei o TanStack React Query no frontend para consumir essas APIs, cache, refetch em segundo plano e atualizações otimistas, para que a UI se mantivesse rápida e consistente sem muita fiação manual de estado.
- **Autenticação e segurança:** Refiz a autenticação, o tratamento de tokens e a validação de payloads da API para atender aos requisitos de conformidade da região.

## Por que importou

O resultado atendeu aos requisitos mais rígidos do mercado de Dubai e estabeleceu um padrão interno mais limpo para como esses apps são construídos. A camada de dados revisada também reduziu chamadas de rede redundantes, o que manteve a experiência rápida para os parceiros de franquia.
