FuelBuddy의 UAE 확장에는 자체 프랜차이즈 앱이 필요했다 — 두바이 시장은 규제, 보안, 워크플로 요구사항이 기존 플랫폼과 달랐고, 그 정도라면 옛 앱을 재사용하는 건 맞지 않았다. 나는 두바이 프랜차이즈 애플리케이션을 맨바닥부터 만들었다 — 프론트엔드와 그 뒤의 CRUD API 양쪽 모두.

## 내가 만든 것

- **맨바닥부터 만든 새 프론트엔드:** 컴포넌트 시스템을 새로 만들어서, 앱이 대체한 이전 버전들보다 더 반응성 좋고 더 잘 짜여지게 했다.
- **Hasura 위의 내 CRUD API:** 앱이 돌아가는 백엔드 데이터 API를 만들었다. 데이터베이스 위에 Hasura의 GraphQL 엔진을 써서 내게 필요한 CRUD 작업을 노출했다 — 그래서 별도의 백엔드 엔드포인트를 기다리는 대신 데이터 계층을 처음부터 끝까지 설계할 수 있었다.
- **TanStack Query 위의 데이터 계층:** 프론트엔드에서 TanStack React Query로 그 API들을 소비했다 — 캐싱, 백그라운드 리페칭, 낙관적 업데이트 — 그래서 수많은 수동 상태 배선 없이도 UI가 빠르고 일관되게 유지됐다.
- **인증과 보안:** 인증, 토큰 처리, API 페이로드 검증을 다시 손봐서 해당 지역의 컴플라이언스 요구사항을 충족했다.

## 왜 중요했나

결과물은 두바이 시장의 더 엄격한 요구사항을 충족했고, 이런 앱을 어떻게 만들지에 대한 더 깔끔한 내부 표준을 세웠다. 개선된 데이터 계층은 중복 네트워크 호출도 줄여서, 프랜차이즈 파트너에게 빠른 경험을 유지해줬다.
